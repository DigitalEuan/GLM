# The One Idea That Builds the Leech Lattice

*An essay on the Golay · MOG · Hexacode · Gray map · Λ₂₄ system, in the spirit of "integration by parts doesn't solve the integral — it transforms it into an easier one."*

---

## 0. The whole thing in one sentence

**Lift the binary Golay code through GF(4) to Z₄, then use the Gray map as an isometric bridge between the Lee and Hamming metric worlds.**

That is the entire generative principle. Everything else in the system — the Miracle Octad Generator, the Hexacode, the three classes of minimal vectors, the dynamic alignment search, the mod-8 glue conditions — is what you get when you run that one idea in different directions. The script in this repository is not a collection of seven clever constructions stitched together. It is one construction, viewed from seven angles.

This essay explains why that one idea works, why each angle is forced, and what the system teaches about how mathematics actually progresses.

---

## 1. Why the Golay code, by itself, is not enough

The binary extended Golay code $C \subset \mathbb{F}_2^{24}$ is a [24, 12, 8] code: 4096 codewords, dimension 12, minimum Hamming weight 8. It is self-dual ($C = C^\perp$) and doubly-even (every codeword has weight divisible by 4). It is one of the most beautiful objects in combinatorics: 759 octads (weight-8 codewords) forming the Steiner system $S(5, 8, 24)$, an automorphism group (the Mathieu group $M_{24}$) of order 244 823 040, and a deep connection to the densest lattice packing in 24 dimensions.

If you wanted to build the Leech lattice $\Lambda_{24}$, the naive approach would be **Construction A**: take $C$, lift it to $\mathbb{Z}^{24}$, and quotient by $2\mathbb{Z}^{24}$. Formally,

$$\Lambda_A(C) = \{ x \in \mathbb{Z}^{24} : x \bmod 2 \in C \} \cup \left( C + 2\mathbb{Z}^{24} \right).$$

This gives a lattice. It is even (every vector has even norm) and unimodular (covolume 1). But it is **not** the Leech lattice. Its minimum norm is 4, not 4-with-196560-vectors. Its kissing number is 4608, not 196560. It is the "wrong" lattice — it's actually $\Lambda_{24}$'s poorer cousin, sometimes called $\Lambda_{24}'$ or the shorter Leech lattice, and it has no interesting automorphisms worth speaking of.

So what's missing? The binary code carries information about *which* integer points are allowed (the parity condition $x \bmod 2 \in C$), but it says nothing about *how* to handle the residue classes modulo higher powers of 2. Construction A only consults $C$ modulo 2. To get the Leech lattice, you need to consult the code **modulo 4** — and that means you need a $\mathbb{Z}_4$-valued version of the Golay code, not just a binary one.

This is the first move of the integration-by-parts mindset: the problem refused to yield in $\mathbb{F}_2^{24}$. Don't push harder. Change representations.

## 2. The lift: $\mathbb{F}_2^{24} \to \mathbb{F}_4^6 \to \mathbb{Z}_4^6$

The lift happens in two stages, and each stage has a name.

### Stage 1: The MOG lift $\mathbb{F}_2^{24} \to \mathbb{F}_4^6$

The **Miracle Octad Generator** (MOG) is a 4×6 grid. You arrange the 24 binary coordinates into the grid (the *arrangement itself* is a nontrivial piece of data — see §6), and then each of the 6 columns holds 4 bits. Conway and Sloane observed that there is a map from the 16 possible 4-bit column patterns to the 4 elements of GF(4) such that, **for every Golay codeword**, the 6 resulting GF(4) symbols form a codeword of the **Hexacode** — the [6, 3, 4] code over GF(4).

The map used in this script is the simplest possible linear one: label the 4 rows of the MOG grid by the GF(4) elements $0, 1, \omega, \omega^2$ (i.e. $0, 1, 2, 3$). For a column pattern $p$, define

$$\text{label}(p) = \bigoplus_{\text{rows } r \text{ with bit } r \text{ set}} r \quad (\text{GF(4) addition}).$$

This is GF(2)-linear: XOR of column patterns corresponds to XOR of labels. It is defined for all 16 patterns (no parity restriction). Its kernel is $\{0000, 0001\}$ — the two patterns with no row set, or only row 0 set, both map to 0.

Why does this work? Because the Golay code is self-dual and doubly-even, which is precisely the condition under which such a linear column-label map can make the Golay code a subcode of the "hexacode constraint" code $\{x \in \mathbb{F}_2^{24} : \text{labels}(x) \in \text{Hexacode}\}$. The latter is a [24, 18] binary linear code; the Golay code [24, 12] sits inside it as a subcode of codimension 6. That's the algebraic shadow of the lift.

The **Hexacode** itself is small: 64 codewords, generated by three basis words over GF(4):

```
(1, 1, 1, 1, 1, 1)
(1, 2, 3, 1, 2, 3)
(1, 1, 2, 2, 3, 3)
```

Its minimum nonzero weight is 4. It is self-dual over GF(4). It is the GF(4)-shadow of the binary Golay code.

### Stage 2: The Hensel lift $\mathbb{F}_4^6 \to \mathbb{Z}_4^6$

The Hexacode is over GF(4), but we want a code over $\mathbb{Z}_4$ (the integers mod 4). The bridge is the identification $\mathbb{Z}_4 / 2\mathbb{Z}_4 \cong \mathbb{F}_2$, generalized to the GF(4) case via the standard $0 \leftrightarrow 0, 1 \leftrightarrow 1, 2 \leftrightarrow \omega, 3 \leftrightarrow \omega^2$ identification.

A $\mathbb{Z}_4$-linear code $\tilde{C}$ is a subset of $\mathbb{Z}_4^n$ closed under addition and under multiplication by scalars in $\mathbb{Z}_4$. Its mod-2 reduction is a binary code $C$. The Hensel lift asks: given $C$, does there exist a $\mathbb{Z}_4$-linear $\tilde{C}$ whose mod-2 reduction is $C$? The answer is: **iff $C$ is doubly-even**, which the Golay code is. (This is a theorem of Hammons, Kumar, Calderbank, Sloane, Pless.)

So the doubly-even property of the Golay code is not a coincidence — it is exactly the condition that permits the lift. The lift exists, and it is essentially unique given the GF(4) shadow (the Hexacode).

The lifted code $\tilde{C} \subset \mathbb{Z}_4^6$ has 4096 codewords (same cardinality as $C$ — the lift is a bijection on the underlying set, but it linearizes the structure differently). It is the input to Construction A on the $\mathbb{Z}_4$ side.

## 3. The Gray map: trading Lee for Hamming

We now have a $\mathbb{Z}_4$-linear code $\tilde{C}$. But $\mathbb{Z}_4$ has a metric — the **Lee metric** — which is different from the Hamming metric on $\mathbb{F}_2^n$:

$$d_{\text{Lee}}(a, b) = \min(|a - b|, 4 - |a - b|) \quad \text{for } a, b \in \mathbb{Z}_4.$$

So $d_{\text{Lee}}(0, 1) = 1$, $d_{\text{Lee}}(0, 2) = 2$, $d_{\text{Lee}}(0, 3) = 1$, $d_{\text{Lee}}(1, 3) = 2$. The Lee metric is the "right" metric for $\mathbb{Z}_4$ because it is the one under which $\mathbb{Z}_4$ embeds isometrically as the vertices of a 4-cycle in the Hamming cube $\mathbb{F}_2^2$.

That embedding is the **Gray map**:

$$\gamma: \mathbb{Z}_4 \to \mathbb{F}_2^2, \qquad 0 \mapsto (0,0),\ 1 \mapsto (1,0),\ 2 \mapsto (1,1),\ 3 \mapsto (0,1).$$

Walk around the 4-cycle $(0,0) \to (1,0) \to (1,1) \to (0,1) \to (0,0)$ in the Hamming cube: each step changes exactly one bit. So Hamming distance in $\mathbb{F}_2^2$ equals Lee distance in $\mathbb{Z}_4$. The Gray map is an **isometry** between $(\mathbb{Z}_4, d_{\text{Lee}})$ and $(\mathbb{F}_2^2, d_{\text{Hamming}})$.

Applied componentwise, $\gamma: \mathbb{Z}_4^6 \to \mathbb{F}_2^{12}$ is an isometry from $(\mathbb{Z}_4^6, \text{Lee})$ to $(\mathbb{F}_2^{12}, \text{Hamming})$. The image $\gamma(\tilde{C})$ is a binary code in $\mathbb{F}_2^{12}$ — but it is **not** the binary Golay code, and it is not even binary-linear in general. It is, however, **$\mathbb{Z}_4$-linear**, meaning it has a hidden algebraic structure that ordinary binary codes lack. This is the secret behind the Kerdock and Preparata codes: they are $\mathbb{Z}_4$-linear codes whose Gray images violate the usual binary-linear bounds but satisfy the (weaker) $\mathbb{Z}_4$-linear ones.

In this script, the Gray map is implemented as the trivial lookup

```python
GRAY_MAP = {0: (0,0), 1: (1,0), 2: (1,1), 3: (0,1)}
```

with a componentwise vector version. The isometry is verified in the demo: $d_{\text{Lee}}(a, b) = d_{\text{Hamming}}(\gamma(a), \gamma(b))$ for all $a, b$.

The Gray map is the **isometric bridge** between two metric worlds. It is what allows us to do combinatorics in $\mathbb{F}_2$ (where counting is easy) while preserving the metric structure of $\mathbb{Z}_4$ (where the lattice lives).

## 4. Construction A on the lift: $\mathbb{Z}_4^6 \to \Lambda_{24} \subset \mathbb{Z}^{24}$

Now we have all the ingredients to build $\Lambda_{24}$. The construction is **$\mathbb{Z}_4$-Construction A**, also called Construction $\Lambda_{24}$:

1. Take the lifted code $\tilde{C} \subset \mathbb{Z}_4^6$.
2. The Leech lattice is the set of integer vectors $x \in \mathbb{Z}^{24}$ such that:
   - The 6 tetrads of $x$ (in the MOG arrangement), reduced mod $2\mathbb{Z}_4$, decode via the inverse Gray map to a codeword of $\tilde{C}$.
   - A **glue condition** mod 8 is satisfied: $\sum_i x_i \equiv 0 \pmod 8$ for vectors in the all-even coset, and $\sum_i x_i \equiv 4 \pmod 8$ for vectors in the all-odd coset.

The first condition says "the binary shadow of $x$ lies in the Golay code." The second condition is the **Leech hole condition**: it kills the root system that would otherwise appear (i.e., it's what distinguishes $\Lambda_{24}$ from the root lattice $D_{24}$ and from the "Construction A on binary Golay" lattice $\Lambda_A(C)$ mentioned in §1).

The glue condition mod 8 is the crux. Without it, you get a lattice with $D_{24}$-type roots (norm-2 vectors) — that is, the shorter Leech lattice. With it, the smallest possible norm becomes 4, and the lattice becomes the Leech lattice, the unique even unimodular lattice in 24 dimensions with no roots.

## 5. The minimal vectors: three shapes, one source

The Leech lattice has exactly 196 560 minimal vectors (vectors of norm 4, in the standard scaling where the squared norm is $32 = 4 \cdot 8$ in the integer representation). They come in exactly three shape-classes, and the three classes correspond exactly to the three cosets of the glue condition.

### Class A: $(\pm 4, \pm 4, 0^{22})$ — 1104 vectors

Two nonzero coordinates, each $\pm 4$, all others zero. There are $\binom{24}{2} = 276$ choices of position, and $2^2 = 4$ sign choices, giving $276 \times 4 = 1104$ vectors.

This class is purely a feature of the integer lattice $\mathbb{Z}^{24}$. It exists in any Construction-A lattice. It is "trivial" in the sense that it does not depend on the code at all — any binary code would give the same 1104 vectors of this shape. Norm: $4^2 + 4^2 = 32 = 4 \cdot 8$. ✓

The mod-8 glue condition is automatically satisfied: $\pm 4 \pm 4 \in \{0, \pm 8\}$, all $\equiv 0 \pmod 8$. ✓

### Class B: $(\pm 2^8, 0^{16})$ on octads — 97 152 vectors

Eight nonzero coordinates, each $\pm 2$, at the support of a Golay octad. There are 759 octads, and for each octad there are $2^8 = 256$ sign patterns, but only $128 = 2^7$ of them satisfy the mod-8 glue condition $\sum v_i \equiv 0 \pmod 8$ (the parity-of-minus-signs must be even). So $759 \times 128 = 97\,152$ vectors.

This is where the Golay code first enters the construction. The choice of octad is a binary-code decision; the choice of which 128 sign patterns are allowed is a $\mathbb{Z}_4$-decision (the glue condition). Class B is the first place where the lift pays off.

### Class C: $(\pm 3, \pm 1^{23})$ controlled by Golay — 98 304 vectors

One coordinate carries $\pm 3$, the other 23 carry $\pm 1$, with signs determined by a Golay codeword. There are 24 choices for the $\pm 3$ position, 4096 codewords, giving $24 \times 4096 = 98\,304$ vectors.

The construction is: pick position $i$ and codeword $c \in C$. Set $v_i = +3$ if bit $i$ of $c$ is 1, else $-3$. For $j \neq i$, set $v_j = -1$ if bit $j$ of $c$ is 1, else $+1$.

The mod-8 glue condition $\sum v_i \equiv 4 \pmod 8$ is satisfied automatically — and this is where the **doubly-even** property of the Golay code is essential. The proof: $\sum v_i = v_i + \sum_{j \neq i} (-1)^{c_j} = v_i + (24 - 2 \cdot \text{wt}(c)) - (-1)^{c_i}$. If $c_i = 1$: $= 3 + 24 - 2\text{wt}(c) + 1 = 28 - 2\text{wt}(c) \equiv 4 \pmod 8$ since $\text{wt}(c) \equiv 0 \pmod 4$. If $c_i = 0$: $= -3 + 24 - 2\text{wt}(c) - 1 = 20 - 2\text{wt}(c) \equiv 4 \pmod 8$ ditto.

This is the deepest class. It uses **every codeword of the Golay code**, not just the octads. The lifted code enters not via the octad supports (which is Class B's job) but via the sign patterns of the $\pm 1$ coordinates. The Gray map isometry is what guarantees that the resulting integer vectors are lattice vectors (not just arbitrary sign patterns).

### Total: $1104 + 97\,152 + 98\,304 = 196\,560$ ✓

This matches the canonical kissing number of $\Lambda_{24}$, confirming that the construction is correct. The script verifies all three class counts and the mod-8 glue conditions as checks V10a–V10i.

## 6. The alignment search: proof by transformation

There is one piece of the construction we have not yet justified: **the arrangement of the 24 binary coordinates into the 4×6 MOG grid**.

The cyclic Golay code (the one built from the generator polynomial $g(x) = x^{11} + x^{10} + x^6 + x^5 + x^4 + x^2 + 1$) has its coordinates indexed $0, 1, \ldots, 23$ in cyclic order. This ordering is natural for the cyclic structure (shifting by one is a code automorphism). But it is **not** the ordering that makes the MOG work. The standard Conway-Sloane MOG uses a different ordering, and that ordering is found by a search.

The script performs this search dynamically, as a **Type 4 proof**: rather than hard-coding the alignment (which would be fragile and would hide the structure), it discovers it from scratch using only the code's intrinsic properties:

1. **Find a sextet.** A sextet is a partition of the 24 coordinates into 6 tetrads such that the union of any two tetrads is an octad. The script searches all $\binom{24}{4} = 10\,626$ 4-subsets; a 4-subset is a tetrad iff it is contained in exactly 5 octads (the $S(5, 8, 24)$ Steiner property). Given one tetrad, the other 5 are forced: they are the symmetric differences $O_i \setminus T_1$ for the 5 octads $O_i$ containing $T_1$. The sextet invariant (union of any two tetrads is an octad) is then verified.

2. **Find a row ordering.** For each tetrad, assign its 4 bits to MOG rows 0–3 (a permutation, 24 options per tetrad). Fix the orderings for columns 0, 1, 2; use the Hexacode basis to predict what the column labels for columns 3, 4, 5 *must* be (given the labels of columns 0, 1, 2 on each generator row); then look up which orderings of columns 3, 4, 5 actually produce those predicted labels.

3. **Verify exhaustively.** Once an alignment is found, the Type 4 test re-checks all 4096 codewords: each one, mapped into the MOG grid, must have its 6 column labels form a valid Hexacode word. Because the column-label map is GF(2)-linear, this condition on the 12 generator rows implies it for all 4096 codewords. Zero failures means the alignment is correct.

This is the integration-by-parts mindset in its purest form. The alignment problem is hard to solve directly — there are $24! \approx 6 \times 10^{23}$ permutations of 24 coordinates. But by using the **Steiner structure** of the octads (which finds tetrads in polynomial time) and the **linearity** of the Hexacode constraint (which collapses the row-ordering search to a small constant factor), the search becomes tractable. The script finds an alignment in under a second.

The alignment search is not a hack. It is a proof that the MOG arrangement exists and is unique up to the automorphisms of the Golay code. The fact that the search succeeds is itself a theorem.

## 7. What the system teaches

The Leech lattice is hard to construct directly in $\mathbb{Z}^{24}$. If you try to write down its 196 560 minimal vectors by brute force, you drown. If you try to find its automorphism group (the Conway group $Co_0$, of order $8\,315\,553\,613\,086\,720\,000$) by enumeration, you never finish. If you try to verify that a candidate lattice *is* the Leech lattice by checking its theta series against the modular form $\Theta_{\Lambda_{24}}(q) = E_4(q)^3 - 720 \Delta(q)$, you need a year of careful computation.

The construction in this script takes a different path. It does not attack $\Lambda_{24}$ directly. It builds a single, small, beautiful object (the binary Golay code), then **transforms the problem** three times:

1. $\mathbb{F}_2^{24} \to \mathbb{F}_4^6$ via the MOG lift. Now the code is 6-dimensional over GF(4), and the Hexacode constraint is a single check.
2. $\mathbb{F}_4^6 \to \mathbb{Z}_4^6$ via the Hensel lift. Now the code has a $\mathbb{Z}_4$-linear structure, which carries the metric information.
3. $\mathbb{Z}_4^6 \to \mathbb{Z}^{24}$ via Construction A with mod-8 glue. Now we have a lattice, and it is the Leech lattice.

The Gray map runs in parallel to step 3, providing the isometric bridge that lets us verify the construction using binary tools (Hamming weights, code linearity) while the lattice itself lives in $\mathbb{Z}_4$ (Lee metric, glue conditions).

Each transformation makes the problem easier. The MOG lift turns a 24-dimensional binary problem into a 6-dimensional GF(4) problem. The Hensel lift turns a discrete-algebra problem into a metric-lattice problem. The Gray map turns a $\mathbb{Z}_4$-metric problem into a $\mathbb{F}_2$-metric problem. By the time we get to $\Lambda_{24}$, we have a construction that is constructive, verifiable, and short — a few hundred lines of code, no floating-point arithmetic, no approximation, every step checkable by exhaustive enumeration.

This is what the integration-by-parts mindset looks like in mathematical practice. When a problem refuses to yield, do not push harder against it. Change its representation. Exploit relationships you already know. Lift, transform, project back. The Leech lattice is one of the hardest objects in 24-dimensional geometry; the Golay code is one of the easiest objects in 24-dimensional combinatorics; the Gray map is one of the smallest isometries in all of mathematics. The deep theorem is that these three facts are not independent — they are three views of the same underlying structure, and the script is a literal proof of that unity.
