# D4 self-transfer utility ledger

`utility.json` is generated by:

```bash
python3 cent-self --write examples/self/utility.json
```

It is a `cent-utility-ledger/1` containing two adopted `cent-utility/1`
records:

| Record | Baseline | Candidate | Delta |
|---|---|---|---|
| `bresenham-quantized-carry-floor` | `32/152` two-tick walk agreement | `152/152` one-tick floor agreement | `+120/152` |
| `junction-runtime-invariants` | `4/12` static topology-audit detection | `12/12` runtime invariant detection | `+8/12` |

The independent oracle in `cent_compiler/self_oracle.py` confirms every injected
fault and issues each `cent-utility-certificate/1`; it is not the candidate
checker. Adoption is explicit and reversible. Re-run a declared rollback with:

```bash
python3 cent-self --revert bresenham-quantized-carry-floor --json
python3 cent-self --revert junction-runtime-invariants --json
```

A reverted record re-runs the named baseline path and reports the restored
value (`32/152` or `4/12`). Re-adopt with `--adopt <id>`. The baseline-only
commands are reproducible too:

```bash
python3 cent-self --baseline --json
```

The ledger is a measurement record, not a physical-device claim. The floor
contract states one-tick exact-model timing only; the existing two-tick
`quantized_carry` target is a different operation and is not relabelled.
