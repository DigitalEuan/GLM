ITERATION 8 PHASE 1 — Junction method for shared Leech coordinates
================================================================================================

Per user input: the 'Junction' GLM method could help — many things are
practically the same operation and the GLM can understand that way also.

The substrate's coordinate_junction.py implements junctions: a junction is
the set of carriers at one exact coordinate vector. For our binary targets,
the 'coordinate' is the Leech CLASS (mod 2Λ). Carriers sharing a Leech class
are in the same junction.

Interpretation:
  * If same_task_rate is high, junctions correlate with task family — the
    GLM can use junction membership as a task discriminator.
  * If same_parity_rate is high, junctions correlate with parity — the
    GLM can use junction membership as a parity discriminator (the user's
    'many things are practically the same operation' insight).
  * If mixed_parity_rate is high, junctions contain both even AND odd
    parity targets — meaning the Leech class doesn't distinguish parity.
    This would be a development issue: the coordinate (Leech class) needs
    to be enriched to separate parity.
