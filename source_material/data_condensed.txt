EXPERIMENT A + C (Note 5) -- Leech/Golay representation vs. raw baselines
================================================================================================

Four solvers on 5 synthetic binary task families, 50 trials each, 4x6 grids (24 bits).

Solvers:
  oracle         -- rule by name (upper bound)
  raw_xor        -- y_q := x_q XOR (x_1 XOR y_1)  [displacement baseline]
  golay_coset    -- work in F_2^24/G_24, transfer the syndrome of the displacement,
                    decode via the canonical coset leader
  random_linear  -- same as golay_coset but with a random 12x24 parity matrix
                    (isolates whether Golay's structure adds anything beyond F_2)

Hypothesis (Note 5):
  * 'toggle' has invariant displacement, so raw_xor, golay_coset, and random_linear
    should ALL succeed on toggle.
  * The other four tasks have non-invariant displacements, so raw_xor should fail.
  * If golay_coset == raw_xor on the non-toggle tasks, the Leech/Golay binary quotient
    adds no transfer power. If golay_coset > raw_xor, that is a real finding.
  * random_linear tests whether any benefit comes from the Golay code specifically
    vs. an arbitrary F_2 linear projection. If golay_coset == random_linear, the
    Golay code's Steiner structure provides no extra benefit here.

================================================================================================

User question: 'where the F_2 multiplication table resolves to F_3,
we could possibly double that resolution F_6 of F_9?'

Note: F_6 doesn't exist as a field (6 = 2*3 has zero divisors in Z/6Z).
But F_9 = GF(3²) is a genuine field extension with a much richer (8-element)

F_9     9     3       8         1             4             deletion (mult by p = 0 in cha  rotation of order 4 (multiplic

Interpretation:
  * 'units' = size of the multiplicative group (the 'spin richness').
    More units => more directions of rotation available to the substrate.
  * 'zero_divs' = elements x where some y != 0 has xy = 0 (the 'punctures').
    In a field, only 0 is a zero divisor; in Z/6Z, both 2 and 3 are.
  * 'spin_order' = the order of multiplication by 2 (or α for extensions).
    F_2: order 0 (deletion, no spin). F_3: order 2 (a swap).
    F_4: order 3 (a 3-cycle). F_9: order 8 (the richest spin here).
  * Higher spin_order => more 'movement directions' the substrate can use.

Key findings:
  * F_2 (parity wall): mult by 2 = 0 (deletion). This is the wall.
  * F_3 (multiplication puncture): mult by 2 = -1 (a swap, order 2).
    The wall is broken; the substrate gains 1 non-trivial spin direction.
  * F_4 (extension of F_2): char 2 still means mult by 2 = 0 in F_4.
    BUT the multiplicative group has order 3 (vs F_2's order 1).
    The 'spin' is multiplication by α (a 3-cycle 1→α→α+1→1).
    F_4 has the SAME characteristic as F_2 (so the basic puncture is the same),
    but it has a RICHER non-trivial multiplicative structure.
  * F_8 (extension of F_2, k=3): char 2 still, mult group order 7.
    The richest 'spin' among the char-2 fields: 7-cycle on the 7 non-zero
    elements. But the puncture (mult by 2 = 0) is structurally identical to F_2.
  * F_9 (extension of F_3, k=2): char 3 (mult by 3 = 0), mult group order 8.
    Combines F_3's puncture-breaking (char 3 not 2) with a richer spin (order 8).
    This is the 'finer resolution' the user predicted: spin_order 8 vs F_3's 2.

Substrate development escalation requirements:
  * If the model needs richer spin directions (multi-step rotations),
    escalate from F_3 to F_9 (spin_order 2 -> 8).
  * If the model needs richer puncture-breaking (more invertible elements),
    escalate from F_2 to F_3 to F_5 to F_7 (the prime fields).
  * If the model needs the SAME characteristic but more spin,
    escalate from F_2 to F_4 to F_8 (char 2, spin orders 0, 3, 7).
  * If the model needs BOTH richer char AND richer spin,
    escalate from F_3 to F_9 (char 3, spin orders 2 -> 8).

================================================================================================

Per rec #1: lift lattice_analogy to Λ_48 so it can TRANSFORM binary targets.

iter9_richer_snap.txt

================================================================================================
ITERATION 9 PHASE 2 — Richer Λ_48 snap (syndrome-coset decoder)
================================================================================================

Per rec #2: extend nearest_lattice_point to Λ_48 by searching C(23) cosets.
The trivial snap from iteration 8 only considered the zero codeword — too coarse.

Algorithm:
  1. Round target to nearest integer
  2. Compute syndrome s = H · (target mod 3)
  3. If s = 0, target is in C(23) — snap = target
  4. If s in weight-1 leaders (96 candidates), snap = target - leader
  5. If s in weight-2 leaders (1128*4=4512 candidates), snap = target - leader
  6. Otherwise, fall back to trivial snap (zero codeword)
