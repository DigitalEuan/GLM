# The corpus held the way the data is: tiers, generation, and an address for every section

## Tier 0 — the coarse read

**Question.** The project's own prose had grown past what one session can read. Can the substrate's rules — generate rather than store, a truncated read is coarse rather than wrong, a derived table only beside the digest of its inputs — be applied to the documents themselves?

**Verdict.** The address does not rank better than reading the words, and what it contributes is a shortlist that is complete up to a stated radius.

**Deciding figure.** Reading every current-state document at tier 0 costs a small fraction of reading them in full, and the completeness bound held on every pair checked with 0 violations.

**Recomputed by.** `glm_universal.corpus.report.corpus_report`

*Tier 0 is a coarse read of what follows, never a claim of its own: the verdict and the figure above are grounded in the body below, and `glm_universal.corpus.checks.tier_report` fails if they stop being.*

---

**What this document is.** Every other study in this repository measures the
machine. This one measures the repository, using the machine's own rules,
because the corpus had reached the size at which "read everything first" stopped
being available and "keep an index" was the answer the project spends its time
refusing. An index is a stored table maintained by hand; it drifts, and nothing
fails when it does.

Four things were built, and each is a rule with a test behind it rather than a
habit.

1. **Tiers.** Every current-state document opens with a tier-0 block — the
   question, the verdict, the one deciding figure, and the function that
   recomputes it. The contract is the delta–sigma contract the substrate keeps
   for a value: *a truncated read is coarse, never wrong*. Tier 0 may say less
   than the body; it may not say anything the body does not.
2. **One generated digest.** [`DIGEST.md`](../DIGEST.md) is those blocks on one
   page, emitted from the documents themselves, so it cannot drift from what it
   summarises.
3. **Archive by rule.** A document is a record of a round exactly when its name
   ends `_ARCHIVE.md`, when it is a session working note, or when it lives under
   a directory named `archive`. Nothing is deleted; the archive simply leaves a
   session's desk.
4. **An address for every section.** The feature map that gives Lean
   declarations a Leech address is applied to prose, so *what in this project
   bears on X?* is answered by a shortlist that is complete up to a stated
   radius — and an empty shortlist is a proof of absence.

Code: [`glm_universal/corpus/`](../glm_universal/corpus/) —
`inventory.py`, `render.py`, `checks.py`, `address.py`, `report.py`.
Command line: `python3 -m glm_universal.corpus`. Formal development:
[`RequestProject/GLM/Corpus.lean`](../glm_lean/RequestProject/GLM/Corpus.lean) and the
shortlist bound it reuses from
[`RequestProject/GLM/Retrieval.lean`](../glm_lean/RequestProject/GLM/Retrieval.lean).
Tests: `glm_universal/tests/test_corpus.py`. Every figure below is
emitted by the function that measures it; the tables are regenerated by

```bash
cd overlay

```

and `--check` fails if one of them has drifted.

The refinement case is worth stating plainly, because it is the honest half.
Requiring the verdict verbatim everywhere would have forced each document to
carry a sentence written for the summary rather than for the reader, which is
the wrong direction: the summary should be derived from the document. So the
weaker test is the one enforced — *tier 0 may say nothing the document does not
say* — and the stronger one is reported beside it, as a count of how many
verdicts are literally quotations.

## 5. An address for every section

The unit is a section: every `##` block of every written document. Each gets two
24-coordinate vectors, both quantised to their nearest Leech point by the same
exact decoder the physical carriers use.

* **lexical** — counts of the section's *distinctive* words by initial letter. A
  word is distinctive when it appears in at most a tenth of the sections; a word
  this corpus uses everywhere (*lattice*, *register*, *measured*) is a property
  of the project rather than of the passage, and counting it pushes every
  section's vector towards the same shape.
* **structural** — counts of the section's *shape*: headings, code fences, table
  rows, links, numerals, quotations, and the words that mark a verdict.

## 6. Does the address retrieve? Measured against its controls

The question is the one the Lean retrieval study asked, in the same form: given
a section, can the address find the rest of the document it belongs to, and does
it beat the controls the house style requires — a digest that knows nothing
about its subject, a seeded reshuffle of the same addresses, closed-form chance,
and the strong control, a plain lexical overlap with no geometry at all?

A retrieved section counts as relevant when it shares a document with the query, or lies in a document linked to it — neither relation is in the feature map, so this is a prediction the scheme can fail.  The lexical address beats chance by 87/20×; plain text overlap still beats it, which is the same division of labour the Lean retrieval study measured.

The answer is the same answer, and it is worth having reached it twice on two
unrelated corpora. The address is a real index — it beats chance, the digest and
the reshuffle. It is beaten decisively by plain text overlap. And the quantiser
is a wash: ranking on the raw identifier vectors scores 18.3 % against 16.7 %
for ranking on their lattice points — one query, the other way round from the
stride this study first measured, which is the honest size of the effect and is
stated rather than hidden.

## 7. What the lattice does earn: a shortlist that is complete

`GLM.Retrieval.complete_shortlist` is a statement about a quantiser onto a
subset of a metric space, not about Lean: if two feature vectors are within
distance `d`, their addresses are within `scale · d + 2ρ`. So collecting every
section whose address lies inside that ball returns a **superset** of the
sections whose features lie within `d` — the shortlist is complete, and an empty
one is a proof that nothing in the corpus is that close.

That is the property that makes a large corpus safe to *not* read, and it is
what the address contributes that the lexical search cannot: a plain search that
returns nothing has found nothing; an address ball that returns nothing has
proved there is nothing to find within the radius.

`GLM.Corpus.lean` adds the part of this round that is a theorem rather than a
measurement: that a tiered read is monotone — a claim visible at tier 0 is
visible at every finer tier, so descending never retracts — that the coarse read
of a document is exactly the tier-0 projection of it, and that an empty
certified shortlist entails the absence of any unit within the feature radius.

## 8. What would falsify this

* A tier-0 verdict that the body contradicts, or a deciding figure whose number
  the body no longer contains: `tier_report` fails, and the suite with it.
* A current-state document that cannot be reached from `ENTRY.md`, or an archive
  document missing from its list: `reachability_report` fails.
* A generated block or a generated document that differs from a fresh rendering:
  `--check` exits 1.
* A pair of sections violating the shortlist bound: `bound_report` fails, and
  the Lean theorem it instantiates would be false of this feature map.

## 9. What this does not claim

The address does not rank better than reading the words, and nothing here says
it does. The tier contract does not make a summary *good* — it makes it
*bounded*, which is a weaker and testable property. And the archive rule does
not decide what is worth keeping; it decides only what a session must load,
which is why nothing was deleted to obtain the reduction in §1.
